# Как собрать пакет `.kege` из PDF и архива файлов

Инструкция рассчитана на человека или ИИ-агента, которому переданы:

- PDF с одним или несколькими вариантами;
- ZIP/7Z/RAR с файлами для заданий;
- PDF, таблица или текстовый файл с ответами;
- название экзамена, год, продолжительность, код активации и пароль эксперта.

Сначала изучите рабочий пример `tools/build_package_example.py` и структуру из `docs/PACKAGE_FORMAT.md`.

## 1. Подготовка исходников

Создайте локальную папку вне отслеживаемых файлов Git:

```text
source_materials/
├── variants.pdf
├── answers.pdf
└── attachments.zip
```

Не коммитьте её. Для официальных открытых вариантов ФИПИ пользователь должен скачать исходники с официального сайта. В публичном репозитории хранится только код сборки и инструкция, но не копия материала.

## 2. Анализ PDF

Определите:

- количество вариантов;
- границы каждого варианта и каждого задания;
- номера заданий;
- продолжение условия на следующей странице;
- тип ответа: одна строка или таблица;
- изображения, схемы и формулы;
- расположение ответов и соответствие вариантам.

Для извлечения текста допустимы `pdfplumber`, `pypdf` или `PyMuPDF`. Если PDF является сканом, используйте OCR, а затем обязательно сравните результат с изображением страницы.

## 3. Перенос условий

Каждое условие хранится в поле `Task.html`.

Требования:

- сохранять полный исходный текст;
- использовать `<p>`, `<table>`, `<sup>`, `<sub>`, `<b>`, `<i>`, `<pre>`;
- экранировать специальные HTML-символы;
- таблицы переносить в настоящую HTML-таблицу;
- программный код оформлять через `<pre>`;
- не использовать скриншот целой страницы или всего условия;
- графики и сложные схемы извлекать отдельными PNG/SVG с достаточным разрешением;
- ссылки на внутренние изображения записывать как `asset://assets/...` и добавлять путь в `visual_assets`.

Рекомендуемая базовая разметка:

```html
<html><head><style>
body { font-family: 'Segoe UI', Arial, sans-serif; font-size: 16px; color: #111827; }
p { margin: 8px 0; line-height: 1.45; }
table { border-collapse: collapse; margin: 12px 0; }
th, td { border: 1px solid #94a3b8; padding: 6px 10px; text-align: center; }
pre { font-family: Consolas, monospace; background: #f1f5f9; padding: 12px; }
</style></head><body>
  <!-- Полное условие -->
</body></html>
```

## 4. Дополнительные файлы

Распакуйте архив в отдельную временную папку. Не полагайтесь только на имя файла: сопоставьте его с текстом задания и структурой архива.

Рекомендуемые внутренние пути:

```text
attachments/<package-id>/v01/task03/data.ods
assets/<package-id>/v01/task01/graph.png
```

В `attachments` укажите понятное отображаемое имя и внутренний путь:

```python
Attachment(name="3.ods", path="attachments/demo/v01/task03/3.ods")
```

Проверьте расширение, размер и возможность открыть каждый файл. Не переименовывайте расширение без преобразования содержимого.

## 5. Ответы

Ключи имеют структуру:

```python
answers = {
    "variant-01": {
        "variant-01-task-01": "42",
        "variant-01-task-17": [["13", "136098"]],
    }
}
```

Для ответа в несколько ячеек используйте двумерный список. Размер должен совпадать с `table_rows` и `table_cols`.

Не добавляйте ответ в HTML и не храните открытый JSON с ключами рядом с `manifest.json`. `create_package()` автоматически шифрует ключи.

Если источник не позволяет достоверно определить ответ, не выдумывайте его. Неоднозначность укажите в `BUILD_REPORT.md`; такой ответ проверяется вручную.

## 6. Создание пакета

Создайте локальный скрипт на основе `tools/build_package_example.py`:

```python
from kege_app.models import Attachment, ExamPackage, Task, Variant
from kege_app.package_io import create_package
from kege_app.security import hash_secret
```

Используйте стабильные идентификаторы в нижнем регистре без пробелов. Один и тот же исходный вариант при повторной сборке должен получать те же ID.

```python
exam = ExamPackage(
    id="fipi-open-informatics-2026",
    title="Открытый вариант ЕГЭ по информатике 2026",
    subject="Информатика",
    year=2026,
    duration_minutes=235,
    activation_code_hash=hash_secret(ACTIVATION_CODE),
    variants=variants,
    source=(
        "Неофициальная техническая адаптация открытого варианта. "
        "Оригинал опубликован ФГБНУ «ФИПИ»: OFFICIAL_URL"
    ),
    answers=answers,
)

create_package(OUTPUT, exam, source_files, EXPERT_PASSWORD)
```

## 7. Автоматическая проверка

```bash
python tools/validate_exam_package.py output.kege \
  --password "EXPERT_PASSWORD" \
  --expect-variants 1 \
  --expect-tasks 27 \
  --strict
```

Строгая проверка должна завершиться кодом `0`.

## 8. Визуальная проверка

Импортируйте пакет в чистую тестовую папку данных и проверьте:

- все задания по очереди;
- отсутствие обрезанного текста и горизонтального смещения;
- таблицы, верхние и нижние индексы;
- масштаб схем;
- сохранение краткого и табличного ответа;
- открытие каждого ODS/ODT/TXT-файла;
- расшифровку ключей в режиме эксперта;
- случайный выбор вариантов;
- экспорт результата.

## 9. Выдача результата

Подготовьте:

```text
Exam_Name.kege
Exam_Name.zip
BUILD_REPORT.md
```

В отчёте укажите официальный URL, дату получения исходников, контрольные суммы исходных файлов и результата, количество вариантов/заданий/вложений, список предупреждений и версию KEGE Station.

Для открытых материалов ФИПИ безопаснее публиковать ссылку на официальный оригинал и эту инструкцию, позволяя пользователю собрать пакет локально. Готовую переработанную копию публикуйте только при наличии подходящих прав или разрешения.
